# Gleave 방향성 점검 09 — AI 보조 기억 분석 및 중복·상충 검토

기준: 2026-10-28 · feat/unified-chat

## 이번 단위

- 기존 `MemoryCandidates` 로컬 휴리스틱 후보 흐름에 **선택적 AI 분석**을 추가.
- 사용자가 프로젝트, 후보 메시지, AI 모델(GPT/Claude/로컬 Ollama)을 확인한 뒤
  명시적으로 동의해야만 분석 API를 호출.
- 이미 Gleave에서 연결된 공급자 스트림을 재사용. 임의 계정 연결·API 키 추출·브라우저
  자동화·Codex 개발 에이전트 실행은 하지 않음.
- 모델에게 보낼 내용은 **선택한 사용자의 원본 메시지 1개(최대 1,600자)**와
  **이미 승인된 프로젝트 기억 최대 12건(건당 최대 400자)**으로 한정.
- AI 출력은 strict JSON schema 검증, 근거 memory ID 존재 검증, 응답 크기 제한,
  민감정보 패턴 검사 후에만 분석 기록 테이블에 영속 저장.
- verdict: new / duplicate / conflict / uncertain. AI가 충돌·중복이라고 평가했지만
  참조할 프로젝트 기억 ID가 없으면 `uncertain`으로 처리.
- UI에는 원문 출처, 모델, 분석 이유, 기존 기억 비교 내역 및 한계 표시.
  후보와 AI 분석은 곧바로 프로젝트 기억이 되지 않음.
- AI의 duplicate/conflict 판단 후에는 별도 위험 인지 체크 및 확인 없이
  승인 API가 거절되도록 서버에서 검사.
- 모델이 `new`라 해도 승인된 기존 기억과 정규화된 내용이 완전히 동일하면
  중복 등록을 거절. 비슷한 문장에 대한 완전한 의미 중복 판단은 보장하지 않음.
- 기존 프로젝트 기억이 분석·승인 사이에 변경되면 분석 지문을 검사하여
  사용자에게 다시 분석하도록 요청. 다중 작업/권한 변경 시 안전 경계.
- 승인·제외 기록은 기존 `chat_memory_reviews` 테이블에서 유지, 출처 기록
  보존 및 사용자/프로젝트 접근 권한을 유지.

## 보안·정확성 한계

- 모델 분석은 **제안이지 검증된 사실이 아니다**. 잘못된 중복·상충 판정이 가능하며
  최종 결정은 사용자에게 남김.
- GPT/Claude 등 클라우드 모델을 고르면 선택한 메시지와 승인된 기존 프로젝트
  기억 일부가 해당 모델 공급자에게 전송될 수 있다. 사용자 명시 동의 필수.
- 로컬 Ollama가 설정되지 않았거나 준비되지 않았다면 즉시 오류를 반환.
- 기존 임시 인메모리 후보 목록은 휴리스틱으로 발견된 imported user 메시지만
  분석할 수 있음. 다른 사람의 원문/타 프로젝트/assistant 메시지는 자동 반영 금지.
- 민감정보 패턴 차단은 완전한 비밀 검출 솔루션이 아님. 실제 팀 인증과 보안 검증,
  기록 감사/삭제 기능은 별도 개발 필요.
- AI를 실제 유료 공급자로 호출하는 end-to-end 계정 검증은 수행하지 않음.
  FakeProvider 기반 모델 호출, 동의, schema 검증, 중복/충돌, 상태 변화의
  계약 테스트 + React 빌드 + GitHub CI로 구현 품질을 평가.

## 앞으로

1. 실제 인증된 GPT/Claude 계정으로 선택 분석 E2E와 출력 품질 평가.
2. 중복/상충 후보의 사용자별 선택 이력 및 더 나은 통합·수정 제안.
3. 프로젝트별 기억 변경/철회·시점 관리, 출처 provenance 시각화, 팀 권한.
4. 장기적으로는 품질 비교를 통한 동적 공급자 선택·비용 제한 및 로컬 추출 모델.
5. 코드 개발 패널/대화 UI와 기억 후보 검토를 통합한 Windows 앱 패키징.
