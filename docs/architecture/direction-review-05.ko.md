# Gleave 방향성 점검 05 — Codex 모델 선택 및 작업 기록 영속화

일자: 2026-10-28
기준 브랜치: feat/unified-chat
검증 상태: 로컬 테스트 진행 후 확정, CI는 Push 후 확인

## 이번 작업

1. 기존 ChatGPT형 대화 화면의 제공자 선택에서 설치된 Codex를 노출.
2. Codex 선택 시 일반 텍스트 Provider로 우회 실행하지 않고, 해당 프로젝트에 연결된 Codex app-server 전용 태스크 API를 호출.
3. 기본 경로는 **readOnly**. 파일을 수정하려면 프로젝트 개발 패널의 workspaceWrite 명시적 승인 절차를 거침.
4. 완료된 Codex 사용자 요청과 결과는 canonical 프로젝트 채팅에 기록되며, 프로젝트 기억과 후속 GPT/Claude 대화가 이를 참조할 수 있음.
5. 같은 채팅의 최근 메시지 일부를 Codex에 비신뢰 참고 데이터로 전달. 프로젝트 밖 원문이나 팀원 개별 채팅은 전송하지 않음.
6. Codex task snapshot, 작업 이벤트, 승인 요청/결정, 종료 결과를 SQLite schema v9에 보관.
7. Gleave가 재시작되면 기존 실행 중·승인 대기 작업은 중단(interrupted)으로 복구하고 승인 대기를 해제. 자동 재실행·자동 승인은 하지 않음.
8. 작업 기록/감사 조회 API는 대화 소유자 확인과 Codex task 소유자 확인을 각각 적용.
9. 채팅 UI Codex 패널은 작업 ID를 전달받아 진행 중 상태 및 추가 권한 요청을 표시하고, 완료 결과 저장이 확인된 뒤 채팅을 갱신.

## 제품 방향 점검

### 목표와 일치
- 사용자는 한 화면 안에서 GPT/Claude와 Codex 사이를 오가면서도 동일한 프로젝트·채팅 맥락을 사용할 수 있음.
- 프로젝트 폴더의 명시적 연결이 곧 메모리·개발 권한의 경계를 의미함.
- Codex 변경 작업은 인프라가 허용한 디렉터리에서만 진행하고 위험 작업은 별도 사용자 동의와 감사 기록이 필요함.

### 아직 미완성
- Codex 실제 로그인된 모델의 종합 코드 수정·diff 검증 E2E 및 타사 공급자 과금 검증.
- Codex 장기 세션을 보존해 재시작 후 동일 thread/turn에서 계속하기.
- 작업 진행 이벤트와 메시지 실시간 스트리밍을 하나의 통합 이벤트 프로토콜로 수렴시키기.
- Claude Code 등 다른 코딩 에이전트와 동일 실행 계약, Smart Router 실측/비용 제어.
- 공식 타사 대화 가져오기 및 승인형 학습 파이프라인, 프로젝트 지식 검색 고도화.
- 인증된 팀 공간, Windows 패키징, 코드 diff/브라우저 미리보기 완성.

## 완료 판정
- Python pytest: Codex agent journal/restart/ACL/approval/컨텍스트 + 기존 대화 회귀 테스트 통과
- React TypeScript 프로덕션 빌드 통과
- 저장소 위생/인코딩 검사 및 GitHub CI 통과
- 실제 모델 수행은 계정/환경 별도 검증 전까지 성공 처리하지 않음

## 개발 시 지켜야 하는 금지사항
- 프로젝트 폴더의 이름만 보고 다른 프로젝트 기억을 가져오면 안 됨.
- Codex를 일반 대화 Provider로 위장해 안전 승인 루트를 건너뛰면 안 됨.
- 중단된 작업을 재시작 뒤 자동 재실행하거나 미확인된 승인을 자동 통과시키면 안 됨.
- Codex의 결과 텍스트만으로 빌드/테스트/배포 성공을 사실로 간주하지 않음.
