# Gleave 방향성 점검 08 — ZIP Import 및 프로젝트 기억 후보 심사

기준: 2026-10-28
브랜치: feat/unified-chat
판정: 개인/프로젝트/채팅 분류 + 승인된 기억 공유 목표에 적합한 확장.

## 개발 변경

- 브라우저의 raw binary upload -> 로컬 Core의 FastAPI Request stream 최대 64MB -> 서버의
  일회용 메모리 스테이징으로 전환. 원본 ZIP 파일은 디스크에 추출하지 않음.
- ZIP 엔트리 수, 상대 경로, 암호화 여부, 무압축 크기와 실제 해제 크기를 검사.
  ChatGPT/Claude는 conversations.json 한 건, Codex는 JSONL 파일 다수 지원.
- 단일 대화 문서 최대 48MB, 세션당 최대 1000개 유효 대화. 선택 20개씩 가져오기.
- 페이지 40건씩 미리보기, 누락된 공급자/만료된 세션/타인 세션 조회 차단.
- 미리보기는 저장되지 않음. 사용자가 확인한 선택만 기존 canonical conversation DB에 트랜잭션으로 저장.
- 기존 provider/source_id 중복 검사, 프로젝트/사용자 소유권 및 메모리 분리 원칙 그대로 유지.
- 인증/메모리 승인 이전에는 임포트된 원문을 자동으로 다른 프로젝트 채팅이나 LLM 학습에 제공하지 않음.
- 사용자 작성 텍스트에서 로컬 규칙 기반 후보를 추출하고, 비밀번호·API 키·이메일 등 민감정보
  패턴이 포함된 후보는 자동 제안하지 않음.
- 후보는 제안 출처 메시지, 이전 대화 제목, 원본 공급자를 보여 주고
  편집 및 명시적 승인/제외 결정을 요청. 결정은 프로젝트별 영속 DB에 남김.
- 승인된 메모리만 프로젝트 문맥에 추가하며, 타인 프로젝트 메시지나 assistant 답변을
  후보로 올리지 않음.

## 제한과 반박 가능한 평가

- 이 단계는 **AI가 학습하거나 심층적으로 기억을 추론하는 시스템이 아니다.**
  초깃값은 로컬 규칙 기반 candidate discovery다.
- 휴리스틱 후보는 의미 없는 문장/부정문을 제안할 수 있어 검수 필수. AI 요약/중복 사실 병합
  및 실제 모델 품질 비교는 후속 과제.
- 마스킹/검출 규칙은 민감정보를 완전히 발견하지 못한다. 팀 프로젝트 승인에는 사용자 주의 필요.
- 파일 업로드는 최대 64MB이고 진정한 chunk/resume 업로드는 아직 구현되지 않음.
  파일 구조·개수·메시지 길이가 임계치를 넘으면 명확하게 거절한다.
- 세션은 로컬 메모리에 최대 30분(또는 서버 재시작 전) 보관되므로 대량 업로드 중
  서버가 종료되면 사용자가 다시 파일을 선택해야 함.
- ChatGPT/Claude/Codex의 공식 export 형식은 변경될 수 있으므로 전체 실제 사용자
  내보내기 호환성은 별도 검증해야 한다.
- 단지 ZIP을 읽었다고 Codex/GPT/Claude를 로그인하거나 구독 동기화하는 것은 아님.
- 로컬 Core의 사용자 헤더 계약은 진정한 인증된 멀티유저 팀 공유 기능이 아님.
- 다른 AI로 가져온 대화를 이어서 질문하면 그 대화가 선택한 공급자에게 전송될 수 있음.

## 개발 완료 조건

- ZIP 미리보기/페이지 조회/선택 Import/중복 방지 및 프로젝트 문맥 격리 테스트.
- ZIP slip/과다 해제/손상 ZIP 및 타인 세션 접근 거절 테스트.
- 승인/제외, 중복 승인 거절, 타인 프로젝트 권한 거절, 기억 컨텍스트 반영 검증.
- React TypeScript 빌드와 Python 코드 스타일, 회귀 테스트, GitHub CI.
- 별도 커밋으로 backend / UI / CI&docs 나누고 원본 main 유지.

다음은 후보 추출을 AI로 바꾸되 **사용자 직접 승인** 원칙을 지키는 방법, 출처 일관성,
중복·상충 후보 심사, 용량 제한 초과 시 chunked/resumable 업로드 개선 순서로 진행.
